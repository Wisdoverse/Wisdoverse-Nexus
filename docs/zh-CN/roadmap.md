# 路线图

Wisdoverse Nexus 仍处于 pre-1.0 工程预览阶段，适用于开发、评估和非生产环境。
这份公开路线图说明工程优先级与验收标准，不承诺固定交付日期或稳定兼容性。

[英文路线图](../en/roadmap.md)是主版本；中文版保持相同的优先级和里程碑状态。

## 产品目标

[项目愿景](../en/design/nexis-vision-design.md)将人与 AI 成员纳入同一套协作模型，
连接房间、文档、会议和工作流。首个支持的产品流程是：团队在房间内讨论工作，
请求身份明确的 Agent 协助，审阅其依据，再批准生成的文档和任务。
身份、上下文、权限和审计记录应贯穿整个跨领域流程。

Rust 网关、协议 crate、Web/移动端和 SDK 是这个流程的基础。
先完成范围小、可验证的协作流程，再扩大提供商、协作领域和部署模式的支持范围。

## 优先里程碑

M1 **实现已合并**；M2 **已实现并通过本地合成验证，真实提供商/人工验收待完成**；M3–M5 **计划中**。仅在验收检查通过，并在公开 issue 或 PR 中关联验证证据后，
才标记为完成。优先级表示实施顺序，不代表发布日期。先完成 M1，再进入 M2；
扩大部署范围前须通过 M3，M4 依赖 M2 和 M3。验证 M4 流程后再进入 M5。

## 执行与质量门槛

[执行标准](guides/roadmap-execution.md)将 M1–M5 拆成 20 个工作包（RD-001–RD-020）；RD-001–RD-004 实现已合并；RD-005–RD-008 有实现和本地合成证据但验收未完成；RD-009–RD-020 计划中，
记录依赖、建议责任角色、进入/完成条件及必需证据。进入 Ready 前指定实际负责人，
只有经过审阅的估算才能用于公布日期。

拟定验收目标包括固定的单节点负载配置、HTTP p95 ≤200 ms、99.9% 网关成功率目标、
明确错误预算、崩溃/恢复检查和 50 个场景的 AI 评测集。
每个目标都要附带样本量、环境、实测值和被测提交。指南明确区分当前 CI 的 60% 工作区行覆盖率下限，
与计划中的变更行覆盖率目标；真实网关门槛已在 [M1 指定版本](../en/guides/m1-acceptance.md)通过，
负载、持续运行、运维和变更行覆盖率目标仍待相应测量与验收。

可信 alpha、评估 beta 和 1.0 候选逐步提高产物、恢复、试用及运维证据要求。
通过路线图工作项模板追踪阻塞和结果。每项 Agent 操作均需授权，写入和外部副作用必须取得人类批准。

## 里程碑验收

### M1 / P0：核心协作流程

实现、已通过的公开 CI 和可复现证据见 [M1 报告](../en/guides/m1-acceptance.md)与
[PR #110](https://github.com/Wisdoverse/Wisdoverse-Nexus/pull/110)。
M1 实现已在 `dc40ae6bb53f9ad7b88b91122113c24ecbc88646` 合并；维护者验收负责人仍待记录。M2 有实现和本地合成证据，真实提供商/人工验收待完成。

围绕支持的认证、房间、消息和 WebSocket 契约，对齐网关、API 文档、Web/移动端和两套 SDK。

验收标准：

- 记录并测试支持的认证流程，包括拒绝无效/过期凭据、房间成员资格，以及文档说明的
  单租户或多租户模式下禁止访问其他房间/租户的行为。
- 使用合成数据，在运行中的网关上演示创建/列出房间、发送/接收消息，验证 WebSocket 认证和重连。
- 对照网关路由和实际提供的 OpenAPI 文档，检查客户端及 SDK 的请求/响应结构。
- 规定稳定的成员/消息标识、会话或回复引用、重连和历史消息行为，使人与 Agent 能引用
  同一项工作。验证重试与重连在支持的恢复窗口内，不会重复已接受消息或静默丢失已确认消息。
- 在 CI 中运行针对真实网关进程的客户端/SDK 冒烟检查；仅通过 mock 测试或构建不足以完成验收。

### M2 / P0：受控的人与 AI 房间试用

M1 完成后，用一个身份明确的 Agent、一种 OpenAI 兼容的提供商配置和一个只读 MCP 工具，
验证 AI 原生协作体验。公开支持的提供商配置，并说明它是本地还是托管服务。
试用仍限定在现有的可信、非生产评估范围内。

验收标准：

- 人类成员在共享房间中明确调用 Agent；展示其身份、进度、流式回答、来源消息引用和
  失败/取消状态。两套 SDK 都能通过文档化契约观察到相同结果。
- 只使用调用成员有权读取的房间数据构建上下文；拒绝访问其他房间/租户，并测试撤销权限。
  将房间内容与工具结果视为不可信输入，不能据此扩大权限。
- 将只读工具限制在明确的允许列表和权限范围内；测试禁止调用、提供商/工具失败、超时和取消。
- 使用 trace 关联请求、上下文来源、工具调用和回答，记录延迟、token 用量和配置的预算上限。
  公开证据移除凭据与私有内容，并说明发送给提供商的数据。
- 在 CI 中针对真实网关运行确定性的合成场景，记录可选的真实提供商冒烟检查，凭据在运行时注入。
  公布回答与权限拒绝场景的通过/失败标准；仅有 mock 覆盖不足以证明提供商互操作。

### M3 / P1：持久化与租户可靠性

在扩大到更多团队或部署模式前，验证一条文档化的存储/部署路径。
让 M1/M2 的身份和策略在重启、恢复和数据留存后继续生效。

验收标准：

- 按文档配置持久化存储后，验证网关重启仍能恢复房间和消息数据。
- 验证 HTTP 和 WebSocket 流程观察到一致的房间/消息状态。
- 按文档中的 feature flag 和存储配置测试租户访问边界，包括拒绝跨租户请求；
  对 Agent 上下文、搜索和已启用的持久化产物应用同样的检查。
- 验证数据留存、导出/删除、备份/恢复和故障恢复路径，覆盖已启用的上下文/记忆/搜索存储。
  保留有用的审计记录，同时避免保留已删除内容或凭据。
- 按文档中的 Compose 部署路径复现启动、升级/迁移和回滚或恢复；
  说明支持的限制，以及它与实验性 Helm 或多节点部署的差异。
- 发布可复现的 benchmark 方法及实测结果，说明环境条件和适用限制。
  测量房间/Agent 端到端流程前先设定工作负载、资源/延迟目标，同时报告失败和吞吐量。

### M4 / P2：讨论形成文档与任务

演示一条完整的跨领域流程：合成的房间对话或提供的会议文字记录形成 Agent 草稿，
人类审阅后批准任务，再将任务状态返回房间。

验收标准：

- 在同一套身份和权限模型下保留来源消息/会议记录引用、文档版本、任务负责人和工作流状态。
- Agent 写入共享文档、创建或分配任务、执行其他外部副作用前，必须取得人类批准。
  测试拒绝、权限撤销、重试/幂等及相应审计记录。
- 验证两个成员通过文档化 CRDT 同步路径编辑后能够收敛，且重启后数据仍在；
  测试冲突与未授权编辑。
- 仅检索有权访问的房间/文档上下文，回答包含来源引用；验证删除或权限变更后无法继续访问旧数据。
- 在 CI 中使用合成数据，针对网关运行讨论到草稿、批准任务再到房间状态的完整场景。
  记录会议文字的手动输入方式；实时会议录制作为独立的后续能力。

### M5 / P3：扩展与外部 Agent 互操作

通过版本化的 MCP/skills/插件契约和一个 A2A 适配器扩展已验证的协作流程。
外部框架经由适配器接入，Nexus 的领域规则继续位于 DDD 应用层/领域层。

验收标准：

- 公布支持的扩展版本、能力/权限范围和兼容性测试；隔离不同集成的凭据与失败。
- 将外部 Agent 的发现、身份、任务状态、取消和结果产物映射到 Nexus 成员及房间/任务引用。
- 固定验收的 A2A 规范版本，与一个外部实现验证完整交接，包括认证和超时场景。
- 说明支持的传输方式和限制；仅有仓库基础类型或命名不足以证明符合协议。

- 保持 `main` 可从全新 checkout 复现，并保留 Rust、移动端、Web、SDK 和文档检查。
- 持续运行依赖审计、密钥扫描和安全问题私有报告流程。

- 保持中英文路线图的优先级和状态一致。
- 为每个里程碑记录依赖、范围明确的工作项和验收证据，根据可复现的试用反馈调整优先级。

## 实验领域

以下领域在仓库中已有代码或设计，但接口仍在演进：

- AI 提供商与 MCP 集成
- 插件与 skills 运行时
- 会议、文档、任务和日历协作域
- 联邦部署与 A2A 设计
- 向量搜索与记忆集成

通过对应里程碑验收后，再扩大到完整会议音视频、通用可视化工作流编辑器、
自主多 Agent 编排、跨实例联邦、公开插件市场和商业计费。
已有模块在其支持的流程通过独立验证前，仍属于实验能力。

## 1.0 前的准入条件

稳定发布前，维护者应为以下项目记录验证证据：

- 完成 M1–M3 和一条 M4 流程，并关联端到端验证证据。
- 说明支持的提供商/工具矩阵，以及 Agent 权限、批准、上下文、用量限制和审计行为。
- 对实际发布的 M5 集成说明范围及协议验收证据；未验证的扩展继续标注为实验能力。
- 发布稳定的 HTTP/WebSocket 和 SDK 兼容策略，包括弃用期限和迁移指南。
- 明确标记实验 crate、端点和集成。
- 验证可重复执行的发布工作流及容器、SDK 产物。
- 记录部署要求、持久化、备份/恢复和升级流程。
- 在 CI 中使用运行中的网关验证客户端和 SDK 示例。
- 提供适用的执行标准门槛报告、明确的负责人/审阅者、容量/支持矩阵、错误预算策略和启用/恢复演练。

已有发布工作流和部署文档构成基础；仍需完成发布和恢复验证。
